## Findings

### H-1 (High) - "Ran 13 of 78" does not balance; the population arithmetic broke in `fd47e9f`

`probe-ci-checker-steps.py:271-281` prints `Ran 13 of 78 run steps` and
then a skip table of `36 + 29 + 1 = 66`. `13 + 66 = 79`, against a
population of 78.

Measured, on `51723c9`:

    Ran 13 of 78 run steps.
    Not run, by category:
       36  multi-line block, has its own setup
       29  not a checker invocation
        1  MUTATES THE TREE or costs minutes

The pre-change probe balanced exactly: `git show
e119e75:docs/reviews/probe-ci-checker-steps.py`, run against this tree,
prints `Ran 12 of 78 run steps, VERBATIM.` with the identical 66 skips -
`12 + 66 = 78`. **The defect is introduced by this merge.**

Cause: the actionlint invocation lives inside the 32-line "Lint the
workflows" step. `classify()` counts that step once in the `36
multi-line block` bucket (`probe-ci-checker-steps.py:164-165`), and then
`main()` appends the invocation line to `runnable` a second time
(`probe-ci-checker-steps.py:250`). The same step is reported as both not
run and run.

It is not cosmetic: the worklog's headline `12 of 78 -> 13 of 78` reads
as "one more of the 78 steps is now covered". What actually happened is
that one *line* was lifted out of a step that is still not covered, so
the honest count of covered steps is unchanged at 12.

This survives even in the degraded paths - with `_ACTIONLINT` forced
never to match, the run prints `Ran 12 of 78` with 67 skips: still 79.

**Suggested fix.** Count the lifted line separately and assert the
identity that would have caught this:

```python
    covered = len(runnable)          # before the actionlint append
    ...
    assert covered + sum(reasons.values()) == len(all_steps), (
        f"population does not balance: {covered} run + "
        f"{sum(reasons.values())} skipped != {len(all_steps)} steps"
    )
    print(f"Ran {covered} of {len(all_steps)} run steps, plus "
          f"{len(runnable) - covered} invocation line(s) lifted out of a "
          "multi-line block (actionlint).")
```

(Prefer a real `if ...: return 2` over `assert`, since `-O` disables
asserts; the shape is what matters.)

### M-1 (Medium) - a real false negative: `python3 -m coverage run <checker>` reads SILENT

`_script_of` returns `None` for any `-c`/`-m`
(`check-checkers-are-wired.py:272-273`). That is right for `-c` and for
`-m <module>` with no script, but wrong for the runner idiom, where a
bare interpreter genuinely executes the checker. Measured against the
real detector:

    python3 -m coverage run docs/reviews/check-checkers-are-wired.py   fires=False
    python3 -m trace --trace docs/reviews/check-checkers-are-wired.py  fires=False
    python3 -m cProfile -o /tmp/x docs/reviews/check-...-wired.py      fires=False

All three ship the `ModuleNotFoundError` this file exists to prevent,
and all three are silent. `ci.yml` runs coverage through
`uv run --frozen pytest --cov` today (`ci.yml:1440`), so nothing is
broken now - this is the next spelling of the founding defect, and it is
the same shape as the `-u` that defeated the regex for a whole day.

**Suggested fix.** Treat a known runner module as a continuation rather
than a terminator:

```python
_MODULE_RUNNERS = frozenset({"coverage", "trace", "cProfile", "profile", "pdb"})
...
            if opt.startswith(_OPT_NO_SCRIPT):
                mod = rest[j + 1] if j + 1 < len(rest) else ""
                if opt == "-m" and mod in _MODULE_RUNNERS:
                    j += 2          # keep walking; the script is further right
                    continue
                return None
```

plus the control row in H-2. (`coverage run` puts a sub-command between
the module and the script, which the existing `not opt.startswith("-")`
break already steps over correctly once `j` advances.)

        raise SystemExit(f"anchor occurs {count} times, expected 1: {frm!r}")

### L-2 (Low) - `ci_is_dirty()` is blind to the index

`probe-ci-checker-steps-control.py:91-97` runs `git diff --name-only --
<ci.yml>`, which compares the worktree to the **index**. A `ci.yml` with
staged-but-uncommitted changes reports clean, so the pre-flight guard at
`:145` ("Refusing to mutate on top of them") does not fire, and the
post-restore check at `:180` cannot see that the restored content
differs from `HEAD`. The docstring at `:86-90` says "whether git sees a
diff", which is stronger than what the command asks.

**Suggested fix.** `["git", "-C", str(ROOT), "status", "--porcelain",
"--", str(CI)]` - non-empty output covers staged, unstaged and untracked
in one call.

### L-3 (Low) - the `--` branch is inoperative, and the row that looks like its control is not

`check-checkers-are-wired.py:267-269`. The branch only changes the
answer when the token after `--` starts with `-`; for anything else the
generic `if not opt.startswith("-"): break` at `:270` reaches the same
token. Measured:

    ['python3', '--', '-x.py']                    -> '-x.py'   (branch load-bearing)
    ['python3', '--', 'docs/reviews/check-...py'] -> same with or without the branch

And any script the branch rescues starts with `-`, which
`_CHECKER_NAME = ^check-[\w-]+\.py$` (`:198`) then rejects. So **no input
exists for which the branch changes `bare_python_steps`'s output.** The
control at `:396`, `(f"python3 -- {needs}", True)`, passes identically
with the branch deleted - it reads as a test of `--` and is not one.
(This is also why the deletion is one of H-2's four survivors.)

**Suggested fix.** Delete `:267-269` and add a one-line comment at `:270`
recording that `--` needs no special case because a checker name can
never begin with `-`; or keep it and label the `:396` row a *shape*
control, not a `--` control. Do not leave it as inoperative code that
looks tested.

### L-4 (Low) - `third_party_imports` is path-blind, so a same-named file anywhere fires

`check-checkers-are-wired.py:211` resolves `ROOT/"docs"/"reviews"/name`
from the **basename** of whatever the walk found. Measured:

    bare_python_steps("python3 /tmp/vendor/check-checkers-are-wired.py")
    -> [('check-checkers-are-wired.py', ['yaml'])]

A vendored or copied file elsewhere in the tree inherits the imports of
the `docs/reviews/` one. No such step exists in `ci.yml` today, so this
is latent, and it fails in the safe (loud) direction.

**Suggested fix.** In `bare_python_steps` (`:311`), reject a script whose
directory is not `docs/reviews`:

```python
        script_path = pathlib.PurePath(script)
        if script_path.parent.name not in ("", "reviews"):
            continue
```

or, better, have `third_party_imports` take the path the walk found and
return `[]` only after proving the path resolves - a lookup that misses
must not read as "stdlib-only".
