## The work

Ordered **timeout -> retry -> breaker**, all in `services/jobvite_client.py`:

- Explicit **per-phase** timeouts. No SDK default, no single scalar. U6 left `request` untouched and
  the paging block sits after it, so this goes around `request` without unpicking anything.
- `tenacity` with jitter, for connection errors, timeouts and 5xx **only**.
- **A configured total outbound budget** bounding all attempts for one tool invocation
  (`DESIGN.md:373-375`) - see the obligation below, it is not optional and it does not exist yet.
- `create_candidate` excluded from retry **by construction**, not by configuration.
- One breaker for Jobvite, **4xx excluded from tripping it**.
- Open breaker and outage both `/problems/service-unavailable` **503**, distinguished by `detail`
  plus a `retry_after` hint.
- `429` retried then mapped to 503, honouring `Retry-After`.

## The breaker: the procedure is FIXED, and it is a rejection test, not a survey

`STANDARDS.md:374-375` blesses `circuitbreaker ^2` and B37 requires one breaker per dependency using
it. An earlier design revision said "no library is selected yet", which turned a one-library
rejection test into an open-ended survey; that is corrected.

**Apply the rejection test to `circuitbreaker ^2` FIRST.** The single experiment:

> **Does it evaluate half-open expiry on the CALL PATH, or from a background timer?**

`DESIGN.md:617` requires the call path. A ContextVar is per-Task, so a half-open expiry fired by a
timer task has no `request_id_var` set, would log `None`, and **would fail §8 #13**.

- If it fires from a timer, it is **rejected ON THE RECORD** with the measurement, and
  `DESIGN.md:602`'s sanctioned inline breaker - a counter, a state and a timestamp checked on entry
  - is taken **with evidence rather than by preference**.
- If it passes, adopt it; it is already a blessed dependency and nothing further is owed.

**Do not survey alternatives before running that one test.** And confirm `^2` is current against the
corpus: the plan read it at `docs/research/STANDARDS.md`, the local digest, which §8 says is not the
authority for currency.

## The verification bar, and one case is not satisfiable by the obvious test

**§8 #13 is CONCURRENT, and a single call does not satisfy it.** `DESIGN.md:1313-1315` states that a
single-call version **passes against a module global**, which is the exact bug `request_id_var`
exists to prevent. So: **two invocations driven in parallel**, each forced to retry, each log line
matched to the invocation that produced it. The same case asserts **no URL appears in a retry line**.

Also required:
- Every breaker transition logs its direction (`closed->open`, `open->half_open`,
  `half_open->closed`), the triggering counter, and `request_id`.
- **§8 #23**: a 4xx does not trip the breaker. **Positive control: repeated 5xx does trip it.** One
  arm alone passes on a breaker that never trips at all.
- **§8 #21**, `create_candidate` not retrying on timeout, asserted with a **ROW COUNTER**, not by
  inspecting configuration. The spike measured one call producing four rows (`DESIGN.md:353`), so
  the assertion is the row count.
- The total outbound budget bounds a slow upstream into a typed 503 rather than an unbounded wait.

## Four things carried in from the board, and the first is an obligation

**1. THE TOTAL OUTBOUND BUDGET DOES NOT EXIST (task #43).** `DESIGN.md:373-374` promises it and
nothing in `src/` implements one. **`config.py`'s `outbound_rate_limit` is NOT it** - a rate limit is
requests per minute; a budget is a time bound on one invocation. They are different quantities and
satisfying one does not satisfy the other. This was found while ruling R2-M6 wrong; do not let it be
closed by pointing at the rate limit.

**2. R2-L-4 is open in your file (task #44).** `jobvite_client.py:539-544` raises
`JobviteUpstreamError` producing `/problems/external-service-error` 502 with the text
**"Jobvite returned status none: ..."**. Reproduced end to end through `problem_from_exception`. It
waited for U6 and then for you. Fix it in this unit - you are rewriting that error path anyway.

**3. THE WIRE PAGE SIZE IS DEFERRED TO YOU DELIBERATELY (task #48).** U6 made it
`min(transport_cap, configured_result_cap)` with no branch, so an exhaustive scan pages at 50 and a
1,240-record resource costs 25 requests against a 6/min self-throttle - about four minutes.
**U6 wrote an "exhaustive scans use the raw transport cap" branch and deleted it itself**, because
the design does not state a paging policy and it had invented one. That was correct.

**My decision: do NOT settle it before the budget exists.** The budget is what determines whether 25
requests is even permissible, so fixing the paging policy first would tune it against the wrong
constraint. Once your budget is real, say in your report what the two interact to produce. If a
policy is then needed, it is a **Proposed ADR**, not a code comment and not a quiet branch.

**4. The rate limit is a GUESS and must say so where it is used.** 6/min is not a vendor figure -
Jobvite documents no numeric limit, only the prose *call it on an as-needed basis, and anything more
frequent than once a day must be filtered*. Checklist row 9 is what would replace the guess with an
observation, and it carries its own safety condition: run it last, stop at the first `429`, never
confirm a limit by exceeding it repeatedly. **Do not run row 9 in this unit.**
