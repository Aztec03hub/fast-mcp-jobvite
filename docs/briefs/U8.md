## The work

- **`models/` for candidates**: allow-listed, `strict=True`, snake_case, **no EEO fields**.
- **`utils/normalise.py`**: casing, epoch-ms dates, `""`/null unification - **both directions**.
- **The fencing half of `utils/redaction.py`**: path-keyed with wildcards, camelCase Jobvite paths,
  delimiter-token stripping, **strings only**, unknown non-string fields **DROPPED not stringified**.
- **`tools/candidates.py`**: `search_candidates` and `get_candidate`.

**Two tools, not one**, and the reason is structural: output cardinality differs - `get_candidate`
returns one record, `search_candidates` a page - and under `strict=True` one tool cannot have two
return schemas.

4. **#24: the `eId`/`EId` casing asymmetry must be PINNED**, so a later refactor cannot tidy it into
   a bug. It looks like a typo and is not.
5. **#20: an unknown non-string field is DROPPED, not stringified.** Assert the drop, not the type.
